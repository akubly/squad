Recursion guard present and scoped correctly. One mandatory fix required (H1): whitespace-only alias bypasses spec contract.

## Critical Findings (Block PR)

None.

## High Findings (Mandatory Before PR)

**H1: Whitespace-only alias bypasses empty-alias guard**
- `const alias = options.developer !== undefined ? options.developer : readDeveloperAliasFromConfig()`
- For `options.developer = " "` (spaces/tabs), alias is truthy — `if (!alias)` does not fire
- Spec contract: "If developer value is empty, exit 1." Whitespace-only is functionally empty.
- Fix: `if (!alias || !alias.trim())` in push-direction guard in `runSync()`
- Probe: `--developer ""` correctly exits 1; `--developer " "` incorrectly proceeds

## Medium/Low Findings

**M1: Push error messages may expose git remote URLs with embedded auth tokens**
- `syncPush()` catch block: `const msg = err instanceof Error ? (err as any).stderr || err.message : String(err)`
- Git push failure stderr may contain remote URL; if URL has `https://<token>@github.com/org/repo`, token appears in output
- Requires already-misconfigured credential-in-URL and console output (not persisted to commits)
- Fix: strip credentials from msg before printing

**M2: `installHook()` force-reinstall duplicates squad section**
- Dead `cleaned` variable never used; execution falls through to append
- Repeated `squad install-hooks --force` compounds hook content indefinitely
- Not a security issue but correctness defect

**M3: No charset allowlist on `--remote` or `stateRemote` values**
- Null bytes or newlines could cause confusing failures
- Piece 30.5 specifies alias format `[a-z][a-z0-9-]{0,38}`
- Apply similar allowlist for remote names: `[a-zA-Z0-9_.-]{1,64}`

**M4: Developer alias lacks charset validation — future injection surface**
- Validated for presence (H1 aside) but not for character set or length
- When refspecs `squad/inbox/<alias>/<session>` land in later pieces, hostile chars will interpolate
- Apply piece 30.5's `[a-z][a-z0-9-]{0,38}` allowlist now

**L1: Hook templates lack `set -eu` strict mode**
- Omit `set -e` and `set -u`; critical calls use `|| true` or `2>/dev/null` as safety valves
- Low risk given coverage; adding `set -e` with explicit `|| true` would improve error visibility

**L2: `cli-entry.ts` dispatch missing `--push` and `--both` handlers**
- `--push` falls to default of `'both'` (correct result, wrong path)
- `--both` also reaches `'both'` (correct)
- Not a security issue; correctness gap
