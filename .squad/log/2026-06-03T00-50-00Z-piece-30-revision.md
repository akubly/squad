## Key Decisions Made

1. **Inline fold pattern:** No new `squad fold` CLI command; fold logic inlined in YAML (bash+jq plumbing).
2. **ADO `batch: true` placement:** Goes inside `trigger:` block (ADO-specific), not top-level.
3. **ADO `persistCredentials` default:** Explicitly set to `true` for any pipeline with post-checkout push steps.
4. **URL scheme positive allowlist:** Accepted: https, http, git+ssh, ssh, git@. Rejected: file, ftp, others.
5. **PAT redaction scope:** Any Write-Host or error message naming a URL must check for embedded credentials.
6. **Execution-based idempotency test:** Uses `120_000ms` Vitest timeout to account for PowerShell startup overhead (×2 iterations).
7. **Docs-test sync hard rule:** New template or state surface requires EXPECTED_FEATURES entry; enforced by CI.

## Learnings for Future Revisions

1. **ADO pipeline concurrency:** Always include `batch: true` in trigger blocks for multi-developer scenarios; otherwise non-fast-forward rejections become operational failures.
2. **Mirror pattern overhead:** 4× file count amplification is inherent to the architecture (3 templates × 4 locations). Factor into scope planning.
3. **Inline CLI logic:** When a subcommand doesn't exist and can't be added (scope lock), inline the logic in YAML/bash rather than creating a new CLI surface.
4. **Security review integration:** Positive-assertion gates (URL allowlist, scheme whitelist) are more effective than exclusion-based gates for injection prevention.
5. **Vitest timeout configuration:** ProcessScript tests need 120s+ timeout due to subprocess startup latency; default 5000ms is insufficient.
6. **Docs-test sync is mandatory:** Any change to test/docs-build.test.ts EXPECTED_FEATURES is a hard gate; enforced by CI and cannot be skipped.
