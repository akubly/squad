### Spec Authorship (Procedures)

Procedures authored comprehensive spec for piece 31: cross-repo CLI wiring fixes. Spec captures five shipping defects discovered during piece-30 code verification:

1. **publishTeamRootToInbox unreachable** — `runSync` dispatches to syncPull/syncPush but never calls publish; ADO publish-inbox.yml invokes `squad sync --push` which only performs state branch push, not inbox publish to remote
2. **stateBackend unwritten** — `runBind` constructs SquadDirConfig without stateBackend field; `detectBackend()` finds null and bails; sync cannot proceed
3. **hydrateTeamRootFromStateRef unreachable** — syncPull fast-forwards squad-state branches in WORK_ROOT; sidecar TEAM_ROOT is never hydrated; function exists but is never called from CLI
4. **SQUAD_DEVELOPER_ALIAS ignored** — ADO pipeline sets env var; runSync checks CLI flag + config.json but misses process.env; pipeline runs without alias
5. **developerAlias unvalidated** — runBind writes any alias to config.json; charset validation DEVELOPER_ALIAS_RE only fires at publishTeamRootToInbox call time, not at config write time

**Code verification:** All five findings verified against shipped code at HEAD of squad/piece-30-ado-cross-repo-templates branch. Line-number citations preserved in spec.

Both fields are required by sub-proposals A and C. The implementer must extend SyncConfig and readSyncConfig() to include these fields. Both fields already exist on SquadDirConfig in SDK (resolution.ts lines 36, 55). This is an implementation prerequisite, not an additional defect.
