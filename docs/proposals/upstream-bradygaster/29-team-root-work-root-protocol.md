# 29 — Team-root / work-root coordinator protocol

## Summary

Replace the single-root path guidance in `squad.agent.md` with an explicit four-path model: `TEAM_ROOT` (docs/specs repo cache clone) carries Squad identity and mutable state; `WORK_ROOT` (product repo) carries code, builds, and tests. This is the minimum coordinator protocol change required to make the cross-repo transport introduced by pieces 26–28 usable in an active session.

Stack position: Part 29 of the cross-repo arc. Depends on piece 26 (config model stable); piece 30 depends on this piece. Template-only change — no `packages/*/src/` modifications.

## Problem

Today `squad.agent.md` instructs all agents to resolve every `.squad/` path against a single "team root." After pieces 26–28 land, two distinct roots exist: the docs/specs sidecar (TEAM_ROOT, writable Squad state) and the product repo (WORK_ROOT, code only). Without an explicit protocol update, agents will continue routing state writes to whichever root their session resolved at startup, silently corrupting state or creating Squad artifacts in product commits.

Piece 26 introduces `TEAM_ROOT`/`WORK_ROOT` in the config model. Piece 28 introduces inbox-branch publish flow where state transport happens via `squad sync`, not direct git operations against WORK_ROOT. Without piece 29, no running coordinator knows how to distribute operations across these two roots.

Three observable failure modes:

- Scribe writes decisions to `WORK_ROOT/.squad/decisions/`, which causes Squad artifacts to appear in product PR diffs.
- Code-editing agents resolve charters and routing from the wrong root, picking up stale or missing team files.
- Spawn prompts omit `TEAM_ROOT` and `WORK_ROOT`, leaving spawned agents to guess root assignment.

## Proposed change

Update the canonical template `.squad-templates/squad.agent.md` to add a four-path table, path-semantics rules, five write rules, and a spawn prompt contract. All five mirror outputs must be byte-for-byte identical to the canonical after `scripts/sync-templates.mjs` runs.

### Four-path table

| Variable | Definition |
| --- | --- |
| `TEAM_ROOT` | Absolute path to the docs/specs repo cache clone |
| `TEAM_SQUAD_DIR` | `{TEAM_ROOT}/.squad` |
| `WORK_ROOT` | Absolute path to the product repo root |
| `WORK_SQUAD_DIR` | `{WORK_ROOT}/.squad` (projection and compatibility cache only) |

`TEAM_ROOT` is authoritative for Squad identity and mutable state. `WORK_ROOT` is authoritative for code, builds, tests, and product git operations.

### Path semantics

- `.squad/team.md`, `.squad/routing.md`, `.squad/casting/**`, `.squad/agents/**`, `.squad/decisions/**`, `.squad/log/**`, `.squad/orchestration-log/**` — always resolved from `TEAM_ROOT`.
- `.copilot/**`, product source, package manifests, build scripts, tests — always resolved from `WORK_ROOT`.
- `WORK_SQUAD_DIR` is a read-only compatibility projection. Never treat it as canonical writable state.

### Write rules

1. Scribe writes only to `TEAM_SQUAD_DIR`.
2. Directive capture writes only to `TEAM_SQUAD_DIR`.
3. Non-Scribe agents must not create or modify files under `WORK_SQUAD_DIR`.
4. Product git operations (branches, PRs, diffs, tests) run against `WORK_ROOT`.
5. State publication happens through `squad sync --push` against `STATE_REMOTE`; never through `git push` from product-repo automation.

### Spawn prompt contract

Every spawned agent receives the following five variables in this order, with no optional omissions:

```text
TEAM_ROOT: <absolute path to docs/specs repo sidecar>
WORK_ROOT: <absolute path to product repo root>
STATE_REMOTE: <remote name, default squad-docs>
STATE_BRANCH: squad-state
DEVELOPER_ALIAS: <alias from .squad/config.json>
```

The Scribe spawn prompt includes an explicit reminder: "write decisions/logs to TEAM_ROOT; do not write under WORK_ROOT."

## Session restart requirement

This piece modifies `squad.agent.md`, the coordinator contract read at session start. Any session active at the time piece 29 merges is operating on the pre-29 single-root protocol and must be restarted before performing Squad path operations under the new model.

The piece-29 commit message and pull request description **must** include the following banner verbatim:

```
🔄 squad.agent.md updated — restart sessions to pick up new path semantics (TEAM_ROOT/WORK_ROOT split). Pre-29 sessions will silently route writes to wrong roots.
```

This requirement is locked by decision Q3. The banner must appear in both the commit body and the PR description — not only in one location.

Coordinator version enforcement (on-disk-vs-session version comparison at session start, with cross-surface support for CLI, VS Code, and GitHub.com) is explicitly out of scope for this piece. It is a separate, future piece noted in Q3.
