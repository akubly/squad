Piece 53 — Hands-off durable review: config-inbox and auto-PR (Pole A capstone). Delivers the durable transport that was deferred by piece 52, symmetric with the ephemeral state fold but gated by a reviewed merge instead of a force-push. The publish path is now lane-aware: `squad sync --push-config` snapshots the team root filtered to `CONFIG_ALLOWLIST` and pushes it to `squad/config-inbox/<callsign>/<dev>/<ts>` — physically distinct from the ephemeral `squad/inbox/**` lane (decision F1), so a ref's prefix fully determines its handling and the two payloads can never cross-contaminate. New callsign-generic, run-time-discovered auto-PR pipeline templates (`fold-squad-config.yml` for GitHub and Azure DevOps) trigger on `squad/config-inbox/**`, overlay the durable payload onto a `squad/config-candidate/<callsign>/<ts>` branch, open a PR into `squad/config/<callsign>` (`gh pr create` / `az repos pr create` under `System.AccessToken`), and delete the inbox ref only after the PR opens — never force-pushing the durable branch. The templates ship the reviewer-gate documentation (CODEOWNERS snippet, `GITHUB_TOKEN` downstream-CI caveat, ADO build-service permission + branch policy). `sync --pull` now hydrates the durable set from `squad/config/<callsign>` (via the registry `configRemote`/`configBranch`) alongside the state hydrate — durable first, then state, disjoint by the piece-52 classifier — recording a distinct `.last-config-hydrate-sha` sentinel so re-pull is idempotent, and skipping cleanly when `configBranch` is unset. `squad status` prints a one-line promotion nudge when a durable file differs from the hydrated config tip, and is silent otherwise.
