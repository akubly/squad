Cross-repo post-commit hook resolves the CLI entrypoint at install time instead of invoking a bare `squad` from the global `PATH`. `installCrossRepoHook` now embeds a resolved `<node> <cli-entry> sync --push --quiet` invocation — `process.execPath` plus the CLI entry script located via `fileURLToPath(import.meta.url)` (probing the built `cli-entry.js`, then the source `cli-entry.ts`, then `process.argv[1]`) — so the installed hook runs the same CLI build that wrote it rather than whatever `squad` happens to be first on `PATH` (no global-install version skew). Both resolved paths are converted to MSYS/POSIX form and POSIX-shell single-quoted so the hook survives git's `#!/bin/sh` execution with Windows absolute paths (drive letters, spaces, backslashes). The two post-commit hook bodies (host-filtered and product) are now builder functions parameterized by the resolved invocation; the `SQUAD_SYNC_ACTIVE` recursion guard, the host variant's `.squad/`-only filter, and the `# --- squad-sync-hook ---` marker idempotency are unchanged. When the entrypoint cannot be resolved, the builder falls back to the bare `squad sync --push --quiet` so an install that previously worked never breaks (piece-45 decision B1). The backend sync hooks (pre-push / post-merge / post-rewrite / post-checkout) invoke `git` directly and are out of scope.
